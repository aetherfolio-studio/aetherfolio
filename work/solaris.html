Solaris 3D Engine

A self-initiated 3D astronomical simulation and hardware-accelerated graphics benchmark uniting Three.js WebGL 2.0, NASA JPL Horizons ephemeris telemetry, custom GLSL atmospheric scattering shaders, and isolated deep space orbital modes into one cohesive, zero-bloat web experience.

Domain Celestial Dynamics
Studio Role Independent Creator
Tech Stack Three.js, WebGL 2.0
Performance 60–120 FPS GPU
01 // Problem & Physical Context

In-Browser Celestial Simulations Suffer from Extreme Scale & Performance Jitter

Representing the Solar System accurately in a browser viewport presents an extreme scale-invariance challenge. The physical radius of the Sun is approximately 109 times that of Earth, while Neptune orbits at an average distance of 30.07 Astronomical Units (AU)—nearly 4.5 billion kilometers from Sol. In traditional WebGL setups, this scale disparity causes severe technical failure modes:

  • Z-Buffer Precision Fighting: Standard 32-bit floating-point depth buffers lose precision when rendering distant planetary orbits alongside micro-detail atmospheric rims, resulting in flickering triangles and occlusion artifacts.
  • Multi-Body Animation Churn: Updating hundreds of independent planetary, moon, and asteroid transforms on CPU main-thread JavaScript creates garbage collection stutter and degrades render loops below 30 FPS.
  • Simplified Orbital Inaccuracies: Most web demos flatten planetary orbits into concentric coplanar circles, discarding eccentricities, semi-major axes, and orbital inclinations required for true astronomical fidelity.

The objective of Solaris was to engineer a hardware-accelerated 3D celestial engine capable of sustaining 60–120 FPS across desktop and mobile devices, pairing NASA JPL Horizons telemetry with Apple-grade typographic restraint and zero external runtime bloat.

02 // Graphics & Shader Architecture

Physically-Based Shading, Rayleigh Scattering & Dynamic Solar Corona

Rather than relying on generic Lambertian textures, Solaris implements custom shader choreographies for every celestial body category:

Rayleigh Atmosphere Scattering

Custom Fresnel rim shaders compute atmospheric optical depth across limb edges, producing realistic blue atmospheric fringes on Earth and amber hazes on Titan.

Procedural Solar Corona

Multi-octave Simplex noise procedural corona flare shader animated over time, generating radiant solar convective granulosity and dynamic limb darkening.

Multi-Pass Normal & Specular Maps

Separate diffuse, normal, specular, and cloud-layer meshes with differential rotational velocity, enabling volumetric storm swirling over planetary topographies.

Translucent Ring Geometries

Double-sided ring plane meshes with radial opacity gradients and Cassini division alpha channels with cast-shadow calculation on Saturn's cloud tops.

03 // Orbital Mechanics

Keplerian Equations & NASA JPL Horizons Ephemeris Calibration

Each orbital trajectory in Solaris is computed from real-world astronomical parameters derived from the NASA Jet Propulsion Laboratory (JPL) Horizons Ephemeris system. Position vectors are derived via eccentric anomaly approximation: 

// Keplerian Orbit Vector Calculation
function computeOrbitalPosition(semiMajorAxis, eccentricity, inclination, meanAnomaly) {
    // Solve Kepler's Equation for Eccentric Anomaly (E): M = E - e * sin(E)
    let E = meanAnomaly;
    for (let i = 0; i < 5; i++) {
        E = E - (E - eccentricity * Math.sin(E) - meanAnomaly) / (1 - eccentricity * Math.cos(E));
    }
    
    // Orbital plane coordinates
    const x = semiMajorAxis * (Math.cos(E) - eccentricity);
    const z = semiMajorAxis * Math.sqrt(1 - eccentricity * eccentricity) * Math.sin(E);
    
    // Apply orbital inclination tilt
    const radInc = (inclination * Math.PI) / 180;
    return {
        x: x * Math.cos(radInc),
        y: x * Math.sin(radInc),
        z: z
    };
}

The simulation includes a real-time time warp engine supporting continuous scaling from 1x (natural relative rate) to 10x and 50x, allowing students and researchers to observe planetary retrograde motion, orbital resonance, and outer-system revolutions without numerical instability.

04 // Spatial Hierarchy

Isolated Deep Space Environment: Moons & Asteroid Belt

To prevent visual clutter in the primary macroscopic view, Solaris introduces an on-demand Deep Space Observatory mode. When activated, the engine swaps to a dedicated high-precision scene graph rendering:

  • Planetary Satellites: Individual high-detail models and telemetry for Europa, Titan, Enceladus, Io, Ganymede, and Earth's Moon Luna.
  • Procedural Asteroid Belt: A GPU-instanced point cloud rendering thousands of individual asteroids with pseudorandom albedos, orbital drifts, and semi-major axes situated between Mars and Jupiter.
  • Seamless Scene Swapping: Zero page reloads or runtime restarts. Transitioning between the macro solar system and micro satellite views executes in under 200ms with smooth camera tweening.
05 // Verification & Outcomes

Hardware-Accelerated Fluidity & Clean Architecture

Solaris achieves instant responsiveness by eliminating heavy framework scaffolding. Built with pure HTML5, CSS3, and Three.js WebGL, it requires no heavy hydration steps or multi-megabyte bundle downloads.

Measured Technical Outcomes
  • Stable 60–120 FPS GPU Render Loop: Hardware-accelerated draw calls execute with under 1% CPU utilization on modern laptops and mobile devices.
  • Zero Cumulative Layout Shift (0.00 CLS): Fixed-dimension canvas viewport and hardware-accelerated transforms ensure zero layout jank during planetary selection.
  • Sub-Second Initial Paint: Complete simulation ready for user interaction in under 800ms on 4G networks.

Frequently Asked Questions About Solaris

What was the technical motivation behind engineering Solaris? add
Solaris was engineered to prove that complex, high-body 3D astronomical simulations can execute smoothly at 60–120 FPS in standard browser viewports without heavy multi-megabyte engine runtimes, combining true Keplerian orbital mechanics with Apple-grade typographic restraint.
How does Solaris ensure accurate planetary trajectories? add
Orbital geometries are calibrated using official NASA Jet Propulsion Laboratory (JPL) Horizons ephemeris datasets, calculating real-time positions via eccentric anomalies, semi-major axes, eccentricities, and orbital inclinations.
How does the rendering pipeline achieve high framerates on mobile devices? add
Solaris isolates heavy render loops into hardware-accelerated Three.js WebGL draw calls, uses procedural shaders for atmospheric scattering and solar flares, and decouples planetary moons and asteroid belts into an on-demand Deep Space scene graph.
